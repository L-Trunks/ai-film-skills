# 仓库里的两类 skill

格式不统一是刻意的，不是遗漏。

---

## 对照

| | 蒸馏型（RIA） | 实操型 |
|---|---|---|
| 代表 | 五个卫星 skill | `local-ai-film` |
| 来源 | 他人公开内容里的方法论 | 作者本人在自己机器上跑出来的 |
| 结构 | R / I / A1 / A2 / E / B 六段 | 装配流程 + knowledge + directing + profiles |
| `source_book` | 有 | 无 |
| 数值可信度 | `verified: 转述` | `verified: 本机实测` + 硬件标注 |
| 数值适用性 | **换环境很可能失效** | 只对标注的硬件组合成立 |
| 测试 | `test-prompts.json` 盲测路由 | 同 |

---

## 为什么不统一成 RIA

RIA 格式（Reading → Interpretation → Application → Execution → Boundary）是为**从他人内容蒸馏方法论**设计的：R 段引用原文，I 段提炼骨架，A1 段记录来源里怎么用的。

`local-ai-film` 没有「原文」。它的内容是作者自己烧 GPU 烧出来的，硬套模板只会造出一个假的引用段 —— 引用谁？引用自己三个月前的踩坑日志吗？

**格式服务内容，不是反过来。** 一手经验用装配流程 + 分类知识库的组织方式更合适。

---

## 为什么不把蒸馏型也改成实操型

因为那需要把五个 skill 的每条方法论都在本机复现一遍，而其中相当一部分**本机根本跑不了**：

- `material-driven-storyboard` 依赖动作迁移驱动视频链路，本机没做
- `rhythm-density` 的秒数来自另一套工具（上限 10 秒），本机 LTX 只有 2.04 秒
- `emotion-to-camera-language` 的五帧实测来自一条云端成片，没法复现

改成实操型就得删掉这些，但它们**作为方法论仍然成立** —— 只是数值不能直接抄。

---

## `verified` 字段是怎么读的

每个 skill 的 frontmatter 里都有一行。三种取值：

| 值 | 意思 | 你该怎么做 |
|---|---|---|
| `本机实测` | 作者在标注的硬件上真跑过 | 换硬件/换模型要重测，方法可信 |
| `转述` | 来自他人内容，作者未复现 | **数值一律当参考，不要直接用** |
| `转述 + 本机实测` | 框架转述，某几条本机验证过 | 看括号里说明了哪几条 |

当前六个 skill 的取值：

| skill | verified |
|---|---|
| `local-ai-film` | 实操型，参数逐项标在 `profiles/` |
| `emotion-to-camera-language` | 转述 + 本机部分验证 |
| `lock-character-reference` | 转述（Qwen-Image-Edit 换机位失效为本机实测） |
| `shot-breakdown` | 转述 + 本机实测（重抽判停为本机实测） |
| `rhythm-density` | 转述（秒数来自来源语料，未在本机复现） |
| `material-driven-storyboard` | 转述（本机未做驱动视频链路） |

---

## 最容易出事的一处

`rhythm-density` 写着「高能段 2-3 秒 / 呼吸段 4-5 秒」。

**这套数来自一个单镜上限 10 秒的工具。** 本仓库实测的 LTX-2.3 上限是 2.04 秒 —— 照抄 4-5 秒的呼吸段，每一镜都做不出来。

该 skill 顶部已加警示框，并把所有绝对秒数改成了随 profile 的 `max_shot_sec` 缩放的比例（疏密比 ≈ 1 : 1.7）。**这正是 profile 机制存在的理由**：同一个仓库里两个 skill 曾经各自把自己那套环境的数当成普适真理，靠 `contrasts-with` 关系互相打补丁。

遇到别的 skill 里有类似的绝对数值，按同样的方式处理：**问一句「这个数是谁的机器测出来的」，答不上来就当转述。**
