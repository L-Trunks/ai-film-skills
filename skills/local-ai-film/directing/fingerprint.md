# 指纹查重

填完 `variables.md` 后必走这一步。**撞维即重来，不许放行。**

---

## 为什么要分两层

只查变量表拦不住真正的重复。

SCP 三部的高层选择完全可以填得不一样，成片照样逐镜同构 —— 因为重复发生在「段落功能 → 具体镜头设计」这一层：

| 位置 | 收容失效 | 站点档案 | 异常现场 |
|---|---|---|---|
| 25（急停） | 摘眼镜擦汗，近乎全黑 | 摘口罩深吸气，近乎全黑 | 摘面具喘气，近乎全黑 |
| 26 | 汗珠滑落反红光 | 瞳孔缓缓放大 | 睁大的眼映火光 |
| 36 | 大远景荒野通风口 | 大远景灰色办公楼 | 大远景公路车开走 |

三部片的 `tempo` 都填 `加速爆发` 没错，但真正暴露问题的是 `peak_device` 全是「摘掉遮脸物 + 近乎全黑」。**这是第二层要拦的东西。**

## films.jsonl 格式

每行一部片，追加写入。位置：`directing/films.jsonl`。

```json
{
  "id": "scp-breach",
  "name": "收容失效",
  "date": "2026-07-20",
  "profile": "ltx-2.3-q4-12g",
  "structure": "trailer-8seg",
  "vars": {
    "time": "线性", "pov": "全知", "tempo": "加速爆发",
    "audio": "BGM通铺", "ending": "空景收"
  },
  "signature": {
    "shot_count": 36,
    "opening_size": "极特写",
    "ending_size": "大远景",
    "peak_device": "摘掉遮脸物+近乎全黑",
    "climax_pattern": "6×极特写连打"
  }
}
```

### signature 五个字段怎么填

| 字段 | 填什么 | 例 |
|---|---|---|
| `shot_count` | 总镜数 | `36` |
| `opening_size` | 第 1 镜的景别 | `极特写` / `大远景` / `中景` |
| `ending_size` | 最后 1 镜的景别 | 同上 |
| `peak_device` | 全片情绪最高点用的手法，一句话 | `摘掉遮脸物+近乎全黑` |
| `climax_pattern` | 高潮段的镜头组织方式 | `6×极特写连打` / `单镜长时凝滞` |

`peak_device` 和 `climax_pattern` 是最容易重复的两项，写的时候**描述手法本身，不要描述题材**。写「摘面具」而不是「防化服人员摘面具」—— 换个题材照样是同一个手法。

## 判定规则

| 层 | 规则 | 比对范围 | 动作 |
|---|---|---|---|
| `vars` | 撞 ≥3 维 | 最近 3 部 | **重选**，硬拦 |
| `structure` | 完全相同 | 最近 3 部 | 警告，须给出显式理由才放行 |
| `signature` | 撞 ≥2 项 | **全部历史** | **重设计**，不论 vars 是否已不同 |

### 「撞」怎么算

- **文本字段**（`opening_size` / `ending_size` / `peak_device` / `climax_pattern`）—— **语义等价即算撞**。「摘眼镜擦汗」与「摘面具喘气」是同一手法的换装，算撞。判不准时**按撞处理**。
- **数值字段**（`shot_count`）—— 差值在 ±10% 以内算撞。36 与 39 算撞，36 与 17 不算。

### 为什么 signature 比对全部历史

`vars` 和 `structure` 只看最近 3 部，是因为高层选择的池子小（5^5 但实际可用组合远少于此），全历史比对会很快无路可走。

`signature` 必须看全部 —— 具体手法的空间大得多，而且**重复隔几部再出现依然是重复**。四部氛围片的 17 镜是隔了几个月分批做的，照样撞。

## 当前历史（初始种子）

已录入 8 部。**三条一眼可见的既有重复，新片请主动避开：**

| 重复项 | 出现次数 | 说明 |
|---|---|---|
| `ending_size: 大远景` | **7 / 8** | 最严重。几乎条件反射式的收尾 |
| `shot_count: 17` | 4 / 4 氛围片 | 全部氛围片同一镜数 |
| `structure: trailer-8seg` | 4 / 4 预告片 | 全部预告片同一骨架 |

新片如果又填 `ending_size: 大远景`，signature 层直接判撞。**这是设计意图，不是误伤。**

## 写回（第 10 步，别漏）

成片验收通过后，追加一行到 `films.jsonl`：

```bash
echo '{"id":"...","name":"...",...}' >> directing/films.jsonl
```

**漏了这一步，整套机制静默失效** —— 下一部片查不到这一部，就会重复它。`../knowledge/pitfalls.md` 坑 ⑧ 的验收清单里有这一条，与抽帧检查同级。
