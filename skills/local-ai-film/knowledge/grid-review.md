# 格子法：逐镜盖章验收

> 适用：一次要出 N 个镜头 / N 张关键帧 / N 段视频的活（N ≥ 8 就值得）。
> 与路线无关，short-shot 和 long-shot 都能用。
> 本文结论来自三部片：87 镜的《办事指南》、58 镜的《镜像》、四段一组的壁纸线。

---

## ⛔⛔ 这套默认不开，要先问用户

**它很有效，但它花的是用户的钱。** 每一轮盖章都要把联络表当图片喂进上下文，
一部片跑下来是几十张图 —— **token 用量和上下文占用会明显上去**，
而且上下文一涨，后面的对话就更容易被压缩、更容易丢前面的判据。

所以：

> **开跑前问一句：「这批要不要走格子法逐镜盖章？会多花不少 token 和上下文，
> 换的是每一格都被我自己看过一遍、不会攒到最后一起爆。」**
> 用户点头才开。

⭐ 例外只有一个：**用户已经明确表达过「这类活一律走格子法、不用每次问」** ——
那就按他的常规办，别每部片再问一遍。除此之外一律先问。

⚠️ 不开格子法时也别退回「跑完就交」。至少做 `pitfalls.md` 坑 ⑩ 那一层
（抽帧拼一张总表通看一遍），和把能算的判据交给 `auto-review.md` 的检查器。
格子法是这两者之上的一档，不是它们的替代。

### 代价长什么样，先跟用户说清楚

| 花在哪 | 量级 |
|---|---|
| 一张联络表（8 镜 × 4 帧，1600 px 左右） | 约 1.5–2 k token 的图像输入 |
| 一部 58 镜的片，8 张联络表通看一遍 | 十几 k |
| 打回重抽 3 轮，每轮重看被打回的那几格 | 再翻一到两倍 |
| 看不清要放大再判的（见下面「我会看错」那节） | 每次又是一张图 |

**省的办法**（值得默认就用）：

- **分批贴**，一次 6–10 格，别把 58 格拼成一张巨图 —— 巨图缩完每格太小，
  等于白贴，还得放大重看，反而更贵。
- **重抽轮只贴被打回的那几格**，已经盖过章的不再入图。
- **能算的先用脚本筛掉**（黑图、脸数、人形数、位置带）——
  机器能判的别拿眼睛判，见 `auto-review.md` ①。
- 联络表存成文件、给路径，不要把中间过程的图重复贴进上下文。

## 是什么

想象一张表，每一行是一个镜头，只有**你自己看过画面并且认可**之后才在那一格盖章。
没盖满之前，这批活不算完，也不许进下游。

```
镜号   状态    指纹          备注
A01    ✅过    3f9c1a2b0e77
A02    ✅过    a1b2c3d4e5f6
A03    ⬜空                  ← 还没跑
A04    ❌退    7e5d…         "特写档没摘服装句，被拉成全身"
```

它要解决的是一个非常具体的病：

> **跑批器报 ALLDONE、文件也都在，于是我说「跑完了」——
> 但我一格都没看过。**

⛔ **「文件在不在」「跑批器报没报错」不是判据，「好不好」才是。**
我们在一天之内在关键帧定稿图、关键帧候选图、视频段三个地方各栽一次，全是这个病。
更狠的一次：自动 gate 全绿的一批，肉眼审片抓出 6 镜背影是错的。

## 怎么落地

### ① 格子由分镜表驱动，不另建一份

盖章表读的应该是**分镜表自己的镜号列表**，不是手抄的。
分镜加一镜，格子自动多一格；删一镜，格子自动少一格。
另抄一份的下场是两边对不上，而且对不上的时候没人会发现。

我们的实现是两个小脚本，`import shots as SB`，靠 `SHOTS` 驱动，不认识具体是哪部片：

```
grid.py                    # 看还差哪些格
grid.py --过 A04,D07       # 盖章
grid.py --退 E22 "理由"    # 打回，理由必填
retake.py                  # 按指纹清场，只重跑被打回的那些
```

### ② ⛔⛔ 盖章必须连提示词指纹一起记

```python
指纹 = hashlib.md5(build_prompt(sh).encode()).hexdigest()[:12]
```

**提示词一改，那一格的章自动失效。** 没有这条，格子法会在两三轮之内
退化回「只看文件在不在」—— 因为你改了提示词重跑，产物名字没变，
章还挂在那儿，你就以为它还是合格的。

⚠️ 顺带一条同源的：**没改提示词的重跑等于白跑。**
H3 同种子完全可复现，提示词一字没动就重抽，出来的是同一段。
被打回的格子，要么改提示词、要么换种子，两样都不做就别按重跑。

### ③ ⛔ 全格盖满之前不进下游

下游（超分 / 剪辑 / 混音 / 上字幕）一跑起来，回头改一格的成本翻十倍 ——
超分件、口型表、音效表、字幕时间轴全要跟着重算，而且这几样里有好几处
**会静默复用过期数据**（见 `pitfalls.md` 坑 ⑲）。

### ④ ⭐ 这一层最划算的位置是关键帧，不是视频段

关键帧十几秒一张，视频段四分钟一段。**不满意就在关键帧层重抽**，
比等视频跑完再返工便宜一个数量级。

所以格子其实该有两层：**关键帧格子全部盖满 → 才开始跑视频段格子**。

## ⛔⛔ 我会看错联络表 —— 这是这套方法最大的失效点

盖章的动作是「我看了一眼，觉得行」。而缩略图上「看了一眼」的可靠度很低。
两次真实误判：

| 我判的 | 实际是 | 怎么发现的 |
|---|---|---|
| 过肩镜前景那块肉色是「一条大腿」，整镜要废 | 是另一个角色的后脑勺 + 裸肩 + 枪带 | 把那一块单独放大重截 |
| 某两镜「虹膜颜色不一致」 | 是缩图的压缩色偏，原图一致 | 同上 |

两次都是**在缩略图上下了结论**，而且两次都差点让我去改一份根本没病的分镜。

> **规矩：拿不准的那一格，先单独放大重截再判，不要在联络表上定罪。**
> 放大一张图的成本，远低于按错误结论改分镜再重跑一轮。

⚠️ 同一条的另一面：**判据要落在你真正要交付的那个文件上。**
量中间目录量得再准都不算数 —— 我们量 `vo\` 说没问题，成片读的是 `vo_剪\`，
连着两轮给出假绿灯。详见 `pitfalls.md` 坑 ⑲。

## 和「无人值守验收」怎么分工

两套不是二选一，是上下游：

```
机器能算的判据（auto-review.md）  →  先筛一遍，黑图/脸数/位置带/跨镜矛盾 直接毙掉
        ↓ 剩下的
人眼盖章（本文）                  →  画风、情绪、构图、表演、"这一镜到底像不像那个人"
```

⛔ **机器判不了的那几样要写明**（`auto-review.md` ⑥）：画风、情绪、构图好不好看。
一份不说自己边界的自动报告，最坏的结果是让人以为「全绿 = 可以出片」，
从而跳过盖章这一遍。我们就是这么放走那 6 镜错背影的。

⚠️ 反过来也成立：**格子法不能代替回归。** 检查器上岗前那一遍误杀回归照做
（`auto-review.md` ②）—— 一个乱杀的检查器会在你盖章之前就把好图移走。

## 什么时候不值得开

- **N < 8**，逐个看比建格子快。
- **一次性氛围片**，本来就是"抽到好的就用"，格子的语义是"每一格都必须成立"，
  用在这里等于给随机性套了个不该有的验收标准。
- **用户明确说了「先跑出来看看」**，那是探针不是交付，探针不盖章。

## 检查清单

- [ ] **开跑前问过用户要不要走格子法，说明了 token / 上下文的代价**
- [ ] 格子的镜号来自分镜表本身，没有手抄第二份
- [ ] 盖章带提示词指纹，改提示词章会失效
- [ ] 被打回的格子，重跑前改了提示词或换了种子
- [ ] 拿不准的格子放大重截过，没在缩略图上定罪
- [ ] 关键帧那一层先盖满，才开始跑视频段
- [ ] 全格盖满之前没有跑超分 / 剪辑 / 混音
- [ ] 机器能算的判据交给了检查器，没拿眼睛去数脸
