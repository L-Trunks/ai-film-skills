# 链式长片的一致性

> 适用：需要把几十个生成段落接成一部片，且**同一个角色要从头贯穿到尾**。
> 与路线无关 —— 短单镜和长单镜都可以链式跑，只是段数不同。
> 本文所有结论来自一部 58 段 / 5 分钟的玄幻短片（minimax-h3-local，736×416，124 帧/段）。

---

## 链式是什么

```
段 0 首帧 = 文生图出的角色定妆图
段 N 跑完 → 抽尾帧 → 存成 PNG → 作为段 N+1 的首帧
```

这样相邻两段在接点上像素级连续，看起来是一镜到底。

代价是**误差会累积**。每一次「抽帧 → 当输入 → 再生成」都是一次有损复制，
角色特征会一路漂移，而且漂移不可逆 —— 一旦白发变成灰发，
后面所有段都在灰发的基础上继续漂。

---

## ① 必须定期重锚定，而且只在幕首锚定不够

**实测**：幕内 6 段就能把「雪白色长发」漂成黑发、「白色广袖长袍」漂成红袍。

只在每一幕开头用文生图重出锚定图 —— 不够。第 19 段（幕首，锚定过）
依然出了黑发，因为漂移在幕内就完成了。

**规则：每 3 段强制重锚定一次。**

```python
anchor_prompt = seg.get("anchor")                      # 幕首显式指定的
if not anchor_prompt and idx % 3 == 0 and idx > 0:     # 幕内定期锚定
    anchor_prompt = "她所在的场景：" + seg["prompt"][:90]
```

锚定 = 用文生图（z-image / SDXL / Flux 都行）**重新出一张首帧**，
切断累积链条。代价是接点不再像素连续，但那一刀落在切点上，看不出来。

---

## ② 锚定提示词必须带完整角色描述 ★

这是最容易漏的一条，也是第 19 段明明锚定过还是漂了的**真正根因**。

```
✗ 锚定提示词 = "她所在的场景：夜里的院子，一口水缸"
     文生图不知道"她"是谁，自由发挥 → 黑发
✅ 锚定提示词 = <完整角色描述> + "她所在的场景：夜里的院子，一口水缸"
```

锚定图是用来**校正**角色的，如果它自己都不知道角色长什么样，
那它校正出来的就是另一个人。

修好之后，25 段到片尾一次没漂。

---

## ③ 空镜绝对不能锚定 ★

锚定图必然带角色 —— 这是它的职责。所以只要一段被锚定，画面里就一定有人。

`idx % 3` 是无差别触发的，它不知道哪一段是空镜。实测：
全片收尾的空镜（「雪山全景，山口的痕迹被雪慢慢盖住，什么都看不见了」）
被塞了一张角色图当首帧，直接变成了又一个人物镜，
把整条「只拍痕迹」的收束线废掉了。

```python
NO_ANCHOR = {57}          # 画面里根本没有人的段
if idx in NO_ANCHOR:
    anchor_prompt = None  # 让它接上一段的尾帧
```

**维护一张空镜清单，写分镜的时候就标出来。**

---

## ④ 主角的属性会渗给同框的所有人 ★

锚定提示词写的是女主「雪白色长发」，结果**同框的男主头发也变成了白色**。
全片男主发色在 5 个段落变白，全部是被锚定过或紧跟在锚定段后面的。

文生图不区分「这句描述是给谁的」，它只知道画面里该有白头发。

### 修法：配角必须有和主角一样完整的定妆描述

```python
✗ MAN = "年轻的持剑男子：短发束起，眉骨明显，眼神清正，穿深青色劲装"
        没写发色 → 模型有自由度 → 白发趁虚而入

✅ MAN = "年轻的持剑男子：纯黑色短发束成利落发髻，眉骨明显，鼻梁高直，
          唇线薄，下颌线清晰，眼神清正，穿深青色劲装，背一柄未出鞘的长剑"
```

并且**锚定图要把同框配角的描述一起带上**：

```python
CHARS = [
    (MAN[:12], "同框还有那个年轻的持剑男子：纯黑色短发束成利落发髻……"
               "他的头发是纯黑色，不是白色。"),
    (TAO[:10], "同框还有那个追捕的道士：花白头发挽成道髻……"),
]
extra = "".join(d for k, d in CHARS if k in seg["prompt"])
anchor_prompt = HER + scene + extra + "画面里的路人一律黑发。"
```

**路人不需要定妆描述**，只约束发色即可 —— 给每个路人写描述是浪费，
而且描述越长越容易触发下面第 ⑤ 条。

### 只写负面词没用

`ZNEG` 里加了「白发男性, 银发男性」照样出白发。
和「负向提示词在 I2V 阶段可能根本不存在」（坑 ⑧）是同一类教训：
**要在正面提示词里把正确答案写出来，而不是在负面里禁止错误答案。**

---

## ⑤ 角色描述里不要写数字 ★

给配角补完整描述之后，画面底部出现了四个大字：**「二十五六岁」**。

模型把提示词里的年龄当字幕画了出来。加之前没有，加了就有，去掉又没了 —— 因果非常明确。

```
✗ "年轻的持剑男子：二十五六岁，纯黑色短发……"
✅ "年轻的持剑男子：纯黑色短发……"
✗ "追捕的道士：五十上下，花白头发……"
✅ "追捕的道士：年长，花白头发……"
```

年龄、身高、数量这类数值一律改用形容词。详见 `pitfalls.md` 坑 ⑫（文字渗漏）。

## ⑥ 尾帧必须抽真正的最后一帧 ★

```
✗ ffmpeg -sseof -0.15 -i seg.mp4 -vframes 1 tail.png
```

`-sseof -0.15` 在 24fps / 5.17 秒的段上抽到的是**第 120 帧**，而全段有 124 帧。
于是段 N 的最后 3 帧演的是「已经越过段 N+1 起点」的内容，
切过去的瞬间画面**往回倒 3 帧**。

这个 bug 在单段检查时完全看不出来 —— 每段自己都正常。
只有连起来看才发现「一顿一顿的」，而且很容易误判成「模型不行」。

**验证方法**：量相邻两段接点处的帧间位移。

```python
d = [abs(fr[i+1]-fr[i]).mean() for i in range(len(fr)-1)]
# 中段均值 6.93，开头两帧只有 1.56 / 0.97 → 开头在"稳定输入图"，几乎不动
```

**正解**：抽最后一帧（`select='eq(n\,N-1)'`），
或者干脆在剪辑阶段把每段的头 2 帧、尾 3 帧掐掉，让结束点和起点严格重合。
后者更稳，还顺带解决了「每段开头有 2 帧几乎不动」的凝滞感。

## ⑦ 剪短镜头时砍头保尾，绝不砍尾

变节奏剪辑（把 5 秒的段剪成 2 秒）时，保留哪一段？

**保尾部，砍头部。** 三个理由，最后一个是硬性的：

1. 剪辑上叫 enter late —— 动作演到一半进画，比从静止起手有劲
2. 生成模型的动作弧线是「起—承—合」，尾部才是落点，砍头保住落点
3. **尾帧接首帧的链条靠「上段结尾 = 下段开头」成立，砍头不动尾，接点原样保住；砍尾就把整条链断了**

## ⑧ 时间轴必须按磁盘实测，不能用计划值推算

剪辑表算出「段 9 保留 100 帧」，ffmpeg 实际吐出 99 帧。
58 段里有 7 段差 1 帧 —— 单看无所谓，但误差会**一路累积到片尾**，
旁白就踩不准画面了。

```python
def timeline():
    for idx, n_planned in rows:
        p = os.path.join(EDIT, "e%02d.mp4" % idx)
        n = frames(p) if os.path.exists(p) else n_planned   # 以磁盘为准
        starts[idx] = cur / FPS
        cur += n
```

同类教训在 `pitfalls.md` 坑 ② 里也出现过：**判定成功要看产物，不要看日志。**
