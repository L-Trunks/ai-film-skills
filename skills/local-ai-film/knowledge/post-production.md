# 后期：从一堆段落到一部片

> 生成只是素材。这一步决定成片像不像"一部片"而不是"一串视频"。
> 顺序有讲究：**接缝 → 节奏 → 分辨率 → 调色 → 声音 → 字幕**，颠倒会返工。

---

## 0. 先剥掉模型生成的音频 ★

如果模型带原生音频（H3 这类），**默认全部丢掉**。

理由是每段各自生成的音乐互不相干：58 段就是 58 段互不搭界的音乐碎片，
连起来极度割裂。这个问题靠"选一个好听的段"解决不了，只能整条重配。

**只有一种情况保留生成音频：需要口型。**
这时提示词里写台词是为了拿口型，音轨仍然后期重配 ——
即"用它生成的口型，配我们自己的声音"。

推论：**不需要口型的片子，台词就不该出现在提示词里**（见坑 ⑫，文字会被画进画面）。

---

## 1. 接缝：掐头去尾

每段掐头 2 帧、去尾 3 帧（具体帧数取决于你的尾帧抽法，见 `chain-consistency.md` ⑥）。

```bash
ffmpeg -i seg.mp4 -vf "trim=start_frame=2:end_frame=$((N-3)),setpts=N/24/TB" \
  -an -c:v libx264 -crf 14 out.mp4
```

**`setpts=N/FPS/TB` 不是可选项。** 用 `PTS-STARTPTS` 的话，
后面 concat 时时间戳会撞车，编码器**静默丢帧**（实测 6062 帧丢成 6013，少 2 秒），
而且丢帧累积 —— 音画会越到后面偏得越多。

---

## 2. 节奏：打破"每镜等长"

生成模型吐出的每一段都是**固定时长**。几十段接起来就是一台节拍器，
每 5 秒一刀、一秒不差。这个机械均匀感比接缝更容易让人觉得"一节一节的"。

### 按幕的情绪定长

```python
ACT_SEC = {
    "化形": 4.96, "入世": 4.0, "相遇": 3.4, "隐匿": 4.6, "暴露": 2.6,
    "追杀": 2.0,  "抉择": 4.6, "决战": 2.4, "归山": 4.96,
}
JITTER = [0.0, 0.35, -0.25, 0.15, -0.35, 0.25]   # 幕内交错，别再整出一个新节拍器
```

### 三条硬规则

**① 段内本来就带硬切的，一律保留全长。** 它自带节奏，再剁就把内部结构剁碎了。

**② 每幕的开场镜头加时（+1.6 秒左右）。**
连切应该是渐进加速，一上来就 2 秒一刀是错的 —— 观众还没认清这是哪儿、来了谁，
就被推着走了。这是剪辑常识里的 establishing shot。

**③ 带旁白的镜头必须装得下它自己那句。**

```python
need = vo_len(idx) + VO_LEAD + VO_PAD if vo_of(idx) else 0.0
if need > sec:
    sec = need
```

不加这条，剁短的镜头装不下 3 秒的旁白，句子就压到下一句上。
这条规则是被撞句逼出来的，**必须按配音的实际时长兜底，不能靠估**。

### 代价

变节奏必然缩短全片（实测 287.6 → 252.9 秒）。**这是要提前告诉用户的取舍**：
5 分钟的节拍器 vs 4 分钟有呼吸。

## 3. 分辨率：超分要按段分治 ★

通用超分模型（ESRGAN 系）对人脸有一条**清晰的破坏阈值**。

| 人脸短边 | ESRGAN 4x 的效果 |
|---|---|
| < 110 px | **破坏** —— 五官熔成一团、脸上长出十字鳞片伪纹理、眼周出硬边 |
| > 150 px | 无害，只是正常锐化 |

原理：通用放大模型对小而糊的人脸没有先验，它必须"填"出细节。
脸大时有足够信息可依，脸小时只能编 —— 编出来的就是伪结构。

受害的主要是**路人和远景配角**，主角近景通常不受影响。

### 修法要在生成阶段，不在后期 ★

**超分补不出生成时就不存在的信息。** 脸小是生成阶段的问题。三条路，按代价从小到大：

#### ① 提高生成分辨率 —— 最直接

脸的像素数正比于画幅。把 0.31 MP 提到 0.5 MP 是 1.30 倍线性放大，
**一张 86 px 的脸直接变成 112 px，正好跨过阈值**。

| 生成分辨率 | 相对 736×416 | 原 86px 的脸变成 | 原 50px 的脸变成 |
|---|---|---|---|
| 736 × 416（0.3 MP） | 1.00× | 86 | 50 |
| 960 × 544（0.5 MP） | 1.30× | **112** | 65 |
| 1152 × 640（0.7 MP） | 1.57× | 135 | 78 |
| 1344 × 768（0.98 MP） | 1.83× | 157 | 91 |

**这张表也告诉你什么时候提分辨率没用**：脸只有 50 px 的镜头，
提到接近 1 MP 也才 91 px，还是不够 —— 那种镜头必须改景别，不是调参数能救的。

代价是显存平方级、时间线性于像素数。12 GB 上 0.31 MP / 124 帧时显存已经 11.5 / 12 GB，
**提分辨率必须拿帧数换**（124 帧 → 107 帧，网格 `17k+5` 决定只能这么跳）。

> 关键是：**不必全片都提。** 只给脸小的那几段提，其余保持原样 ——
> 反正后期都要统一超分到同一尺寸，各段生成分辨率不一致完全没问题。
> 这和下面的「按段分治」是同一个思路，只是作用在生成阶段，效果好得多。

#### ② 改景别 / 换构图重抽

中景改近景、把人从画面深处挪到前景。**换种子重抽解决不了这个问题** ——
同一个构图换个种子，脸还是那么小。只有改构图才有用。

#### ③ 换种子重抽

只对"构图没问题但这一版画糊了"有效（蜡质感、运动模糊糊掉脸）。
本片有三段是这么修好的，效果和后期挽救不是一个层级。

### 兜底修法：按段分治

来不及重抽时才用这个。

```python
FACE_MIN_PX = 110
small = {r["seg"] for r in blur_json if r["face_px"] < FACE_MIN_PX}
# 脸小的段走 lanczos 原生放大（软但不假），其余走 ESRGAN
```

**要清楚它做的是什么：不是把脸修好，是不去编造。**
脸该糊还是糊，只是从"编错的五官"退回到"看不清的五官"——
在小脸上后者更耐看，仅此而已。

段与段之间本来就是切点，处理方式不同看不出来。
**原生放大的段必须缩放到和超分档一样的尺寸**，否则 concat 会在那里断掉。

### 人脸修复（CodeFormer / GFPGAN）：对非人角色是负资产 ★

实测把「浅琥珀金瞳」改成了灰蓝色，还加重眼线、加饱和唇色，
变成一张更"标准"的漂亮脸。**`fidelity` 调到 0.9 都拦不住** ——
这类模型对"正常人脸"的先验太强，妖瞳、异色瞳、非常规眼型它一定给你掰回去。

结论：**奇幻 / 科幻角色不要用人脸修复**，只超分。
副作用是快一倍多（35s/段 vs 81s/段）。

## 4. 调色：统一，不是风格化

各段独立生成，白平衡和对比度都有细微差别，逐段看不出来，连起来就一节一节的。

```
eq=contrast=1.06:saturation=0.93:gamma=0.99,
curves=all='0/0.015 0.5/0.5 1/0.985',
colorbalance=rs=-0.025:bs=0.045:rm=0.012:bm=-0.012:rh=0.02:bh=-0.02,
vignette=angle=PI/5.5,
noise=alls=2:allf=t+u
```

**手要轻。** 目的是把不同场景（雪原/竹林/夜审/火把）黏成一个片子里的东西，
不是给它加风格。

## 5. 声音

### 旁白

一条统一音色贯穿。Edge TTS 的中文男声在 2026-08 只剩四个
（Yunjian / Yunxi / Yunxia / Yunyang），`Yunye / Yunze / Yunfeng` 已下架 ——
**别照抄网上的音色列表，先 `list_voices()` 查一遍。**

时间轴与画面同源，逐句放到它所属段的起点后 0.6 秒。

**旁白跨过剪辑点是好事**（能把段落黏起来），只有"下一句已经开口"才算撞车：

```python
nxt_at = starts[nxt] + LEAD_OVERRIDE.get(nxt, LEAD)
if end > nxt_at:
    collisions.append((idx, nxt, end - nxt_at))
```

### BGM

**一条贯穿，不要每段配。**

选曲不能只靠频谱指标。第一轮按质心/滚降/低频占比选出来的古筝曲被判"不对味" ——
指标只量音色，量不到"它是在垫底还是在抢戏"。
**做几条 45 秒试听片（画面 + 旁白 + 候选 BGM），放进片子里听。**

铺满全片不要用 `aloop` —— 硬循环在接点上是一次突兀的重启。
用曲子和自己做交叉淡化：

```bash
[1:a]aresample=48000[b0];[1:a]aresample=48000[c1];
[b0][c1]acrossfade=d=4:c1=tri:c2=tri[b1]
```

### 混音

旁白做 sidechain 把 BGM 压下去，保证人声始终清楚：

```
[bg][key]sidechaincompress=threshold=0.02:ratio=8:attack=15:release=450[bgd]
[vo][bgd]amix=inputs=2:normalize=0[mx];[mx]alimiter=limit=0.95[a]
```

### 许可

CC0 和 CC-BY 不一样。**CC-BY 发布时必须署名**，
`ND`（禁止演绎）和 `SA`（传染许可）一律不能用作 BGM ——
把音乐配到视频上通常构成演绎作品。抓取时就要过滤，并把许可写进 manifest。

## 6. 字幕

用 ASS（libass），不用 SRT —— 需要指定字体、描边和垂直位置。

```
[Events]
Format: Layer, Start, End, Style, Name, MarginL, MarginR, MarginV, Effect, Text
Dialogue: 0,0:00:00.60,0:00:06.54,VO,,0,0,0,,山里有个说法：狐狸活过五百年……
```

**`Format` 行必须写完整的 10 个字段。** 只声明 5 个却按 10 个的习惯多打一个逗号，
那个逗号会被当成正文首字符 —— 每行字幕前面凭空多一个逗号。

时间轴与旁白同源（同一个 `timeline()`），所以字幕和人声必然对齐。
相邻两句要防叠字：

```python
if rows[i][1] > rows[i+1][0] - 0.1:
    rows[i] = (rows[i][0], rows[i+1][0] - 0.1, ...)
```

烧进画面时显式给 `fontsdir`，别指望 fontconfig：

```bash
subtitles='E\:/path/subs.ass':fontsdir='C\:/Windows/Fonts'
```

## 7. 总装

```bash
ffmpeg -f concat -safe 0 -i list.txt -i bgm.mp3 -i narration.wav \
  -filter_complex "[0:v]setpts=N/24/TB,<调色>,<字幕>[v];<音频链>" \
  -map "[v]" -map "[a]" -c:v libx264 -crf 17 -preset slow -pix_fmt yuv420p \
  -c:a aac -b:a 192k -shortest out.mp4
```

**验收要数帧**，不要只看时长：

```bash
ffprobe -count_frames -select_streams v:0 -show_entries stream=nb_read_frames out.mp4
# 应当等于各段帧数之和。对不上就是 concat 丢帧了。
```

## 顺序为什么是这个顺序

| 步骤 | 为什么不能往后挪 |
|---|---|
| 剥音频 | 决定了提示词里要不要写台词，影响生成本身 |
| 接缝 | 掐头去尾会改变每段帧数，节奏和时间轴都建立在这之上 |
| 节奏 | 剪短会改变时间轴，旁白和字幕都要按新时间轴排 |
| 超分 | 在剪辑之后做只需处理保留的段；在剪辑之前做是白烧 GPU |
| 调色/字幕 | 总装时一次过，重复编码会掉画质 |
