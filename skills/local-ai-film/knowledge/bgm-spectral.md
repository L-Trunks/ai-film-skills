# 声音

**全部通用**——与生图/生视频模型无关，换模型不必重测。

工具：`../examples/scripts/bgm_pick.py`（体检 / 选曲）、`bgm_fetch.py`（按档抓无版权曲）。
两个都零新依赖（ffmpeg 解码 + numpy FFT）——**不要往跑模型的环境里装 librosa**，
numba/numpy 版本冲突会毁掉 ComfyUI。

---

## 〇、这片子该配哪一档

先定档再找曲，不要拿着曲子问「配不配」。判据取自 `../directing/variables.md` 的三个维度：

| 变量表取值 | 倾向档位 | 为什么 |
|---|---|---|
| `tempo: 匀速` + `ending: 空景收` | 清新通透 / 深邃 | 没有张力曲线，靠音色本身撑 |
| `tempo: 加速爆发` | **深邃有质感** | 需要低频托底，爆发段才有重量 |
| `tempo: 前紧后松` / `两次呼吸` | 深邃有质感 | 同上，且后段放慢时低频是唯一的连续性 |
| `pov: 监控·仪器` / `缺席` | 深邃 → 压抑 | 视点本身冷，配亮曲会打架 |
| `ending: 硬切黑` / `悬而未决` | 压抑惊悚 | 不给收束的片子需要不解决的和声 |
| `ending: 日常化` | 清新通透 | 从异常回落到日常，音色要跟着回暖 |

⚠️ **「压抑惊悚」这一档要慎用。** 它的滚降低到 ~440 Hz，本质是低频嗡鸣；
用在没有明确惊悚意图的片子上会被判「诡异」而不是「压抑」。
拿不准就选深邃档 —— 它能覆盖大多数氛围片。

### 定档之后

```bash
# 1. 先看现有曲库有没有能用的
python bgm_pick.py <曲库目录> deep

# 2. 不够就按档抓新的
python bgm_fetch.py deep --n 7
```

## 一、选 BGM 不能只看节奏强度

按「节奏最低」选过一首 `Ambiment`，被判「诡异」。原因：它的**频谱滚降只有 447 Hz**，85% 能量压在 447 赫兹以下，本质是低频嗡鸣。

必须同时量三项：

```python
import librosa
y, sr = librosa.load(path)
cen = librosa.feature.spectral_centroid(y=y, sr=sr).mean()   # 质心：亮度
rol = librosa.feature.spectral_rolloff(y=y, sr=sr).mean()    # 滚降：高频空气感
ch  = librosa.feature.chroma_cqt(y=y, sr=sr).mean(axis=1)    # 大调 ch[[0,4,7]] vs 小调 ch[[0,3,7]]
```

三档参考（实测）：

| 要什么 | 质心 | 滚降 | 低频占比 | 调性 |
|---|---|---|---|---|
| 清新通透 | ~2000 Hz | ~4200 | 15% | 大调 |
| **深邃有质感** | ~1400 Hz | ~2960 | **33%** | **小调** |
| 压抑惊悚 | ~550 Hz | ~440 | 61% | — |

⚠️ **深邃 ≠ 发闷，分界在滚降。** 低频占比高才「深」，但滚降必须保住 ~3000 Hz 才有质感 —— 滚降掉到 440 Hz 就是一条低频嗡鸣，会被判「诡异」。

## 二、成片音量分两套标准，别套错

| 片型 | 目标 RMS | 理由 |
|---|---|---|
| 有旁白的科普/教程片 | 0.05–0.06 | BGM 要压在人声下面 |
| **无对白氛围片** | **0.075** | BGM 是唯一音轨，可以饱满 |

拿前者的标准去做后者，整批会偏轻 —— 13 部片实测只有 0.017–0.068，直接被反馈「偏小」。

## 三、`bgm_vol` 别指望一次调准，事后统一调平

按曲目自身 RMS 反推系数，实测**每次都偏保守** —— 19 部片没有一次一步到位（0.017–0.068，目标 0.075）。

原因是成片 RMS 还受转场淡入淡出、`afade` 首尾、以及素材本身有没有环境声影响，**算不准**。

**正确做法**：`bgm_vol` 随便给个大致值，出片后统一跑 `examples/scripts/regain.py` 调平。一次处理整个成品目录，只重编码音轨、视频流 copy，几秒一部，画质零损失。

核心逻辑：

```python
gain_dB = 20*math.log10(TARGET/current_rms)
gain    = min(gain_dB, -max_volume - 0.5)      # 削波保护
# ffmpeg -i in.mp4 -af volume={gain}dB -c:v copy -c:a aac -b:a 192k out.mp4
```

⚠️ 解析 `volumedetect` 的输出时注意 `pitfalls.md` 坑 ④ —— stderr 不能用 `text=True` 读，否则 `max_volume` 拿不到，削波余量取默认值，整批增益被卡在 +0.5 dB，**表面上跑成功了但实际几乎没调**。

## 三点五、曲库要定期体检

九部片全部用同一批 6 首曲子。跑 `bgm_pick.py` 一体检，两个问题当场暴露：

**① 有重复文件。** `cand_fearless.mp3` 与 `hype.mp3` 的 MD5 完全相同 ——
名义 6 首，实际只有 5 首。频谱指标一模一样是发现它的线索。

**② 分布严重失衡。**

| 档位 | 曲目数 |
|---|---|
| 清新通透 | 1（还是那个重复文件） |
| **深邃有质感** | **3** |
| 压抑惊悚 | 1（且是被判「诡异」的那首） |

**这就是为什么九部片的 `audio` 维全是 `BGM通铺`** —— 不是不想变，是没得选。
曲库的多样性直接限制了创作的多样性，这一点很容易被忽略，因为它不表现为「BGM 不好听」，
而表现为「所有片子听起来像一个系列」。

**每档保持 5–8 首**，用 `bgm_fetch.py` 补齐。

## 三点六、许可与署名

`bgm_fetch.py` 每留下一首就往曲库目录的 `LICENSES.jsonl` 追加一行，记录
标题 / 许可 / 作者 / 来源页 / 实测频谱值。

| 许可 | 发布时要做什么 |
|---|---|
| CC0 | 无需署名 |
| **CC-BY** | **必须在视频描述里署名作者** |
| Pixabay Content License | 无需署名，但不可原样转售音频本身 |

⚠️ **清单在脚本结尾才写。** 抓取中途被杀会留下一堆没有署名记录的音频文件 ——
踩过（见 `pitfalls.md` 坑 ② 的连带伤害）。没有对应 `LICENSES.jsonl` 条目的曲子
**不要用**，宁可重抓。

## 四、声音维度与变量表的关系

`directing/variables.md` 的「声音」维有五个取值，本文只覆盖 `BGM通铺` 一种。其余四种的做法：

| 取值 | 要点 |
|---|---|
| BGM通铺 | 本文全部内容 |
| 音效驱动 | BGM 降到 0.03–0.04 只作底，靠逐镜音效撑；预告片走这套 |
| 环境声 | 不用 BGM，全靠现场声（雨、风、街声）铺满；素材本身无声，需另配 |
| 完全静音 | 只有极少数镜有声，其余纯静。最难，留白时长要精确设计 |
| 声画错位 | 声音属于上一镜或下一镜，制造不安。需逐镜排 offset |

后四种本仓库尚未实拍验证，标注 `verified: 未自测`。**首次使用建议先做 20 秒短片试。**
