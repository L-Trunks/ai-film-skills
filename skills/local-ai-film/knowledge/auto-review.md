# 无人值守验收：把「我拿不准」变成一个能算出来的数

> 前置：`pitfalls.md` 坑 ⑩「验收必须抽帧，不能只看日志」讲的是**验收要看画面**。
> 本文讲的是下一层 —— 画面看了，**没人在旁边判**的时候怎么办。

跑批只要一进夜里就会撞上同一个问题：某一张图**我判不准**。
白天的答案是「问一句」，夜里没人可问，于是自然的做法变成「攒着，早上一起问」。

**这是错的。** 攒一夜等于停摆：下游（H3 一集三小时、每段要重启 ComfyUI）根本没开跑，
一夜 GPU 全白烧。要的不是把决定推回给人，是**把判据变成能算出数的东西**。

---

## ① 先问：这个判断能不能变成一个数

大多数能。而且大多数不需要 VLM，也不需要花钱的 API —— 现成的 CV 就够：

| 分镜里写的要求 | 变成什么数 | 用什么 |
|---|---|---|
| 「完全背对镜头」 | 人脸检测数 == 0 | insightface `buffalo_l` |
| 「人在画面左三分之一」 | 人体 bbox 中心 x < 0.42 | keypoint R-CNN |
| 「全景，看得到整个人」 | 膝/踝关键点 score 都 > 阈值 | 同上 |
| 「这是物件特写，画面里没有人」 | 人脸数 == 0 且人形数 == 0 | 两者都要 |
| 生成直接翻车（黑图/糊成一片） | 全图像素 std < 6 | 一行 numpy |

**判据要从分镜自己的声明里推**，别另写一份。我们的做法是分镜里已经有
`lead=`（夹句）、`pose=`、`band()` 这些字段，验收脚本读同一份数据反推该查什么 ——
这样改了分镜，判据自动跟着改，不会漂。

⛔ **人脸检测器放 CPU 跑。** 它和生成任务抢的是同一张卡，
验收本身把显存吃掉、导致下一张图 OOM 是很蠢的死法。

## ② ⛔ 检查器上岗前必须回归，查的是「误杀」不是「漏杀」

这条是整篇最重要的。**一个没验证过的检查器，会整夜按错误的判据杀好图**，
比不装检查器坏得多。

做法：拿**已经出片、已经人工认可**的历史素材跑一遍，凡是被判不合格的，
都是你自己的假阳性。我们拿 59 张已出片的关键帧跑，揪出三类：

| 假阳性 | 长什么样 | 修法 |
|---|---|---|
| **方向词被当成位置词** | 分镜写「他看向画面右边」，被解析成「他在画面右边」 | 只从结构化字段取位置，不从自由文本里正则抠 |
| **肢体被当成人** | 一个贴地只拍鞋的镜头，检出「8 个人」 | 加一道「头部关键点 score > 5」才算一个人（实测真人 8.6–19.9，肢体 −0.7…−2.7） |
| **量错了人** | 过肩镜里前景配角的背影 bbox 比主角大，于是量了配角 | 优先取**有头的**最大框；≥2 个人形直接判「存疑」不判不合格 |

顺带的收获：这轮回归**独立查出 4 处已出片素材的真实缺陷**
（两镜写了「完全背对」出的是正面、一个肢体特写里被塞了张 64px 的脸、
一个要求无人的镜里有个人形）。回归不只是自查，它也是免费的复检。

### 记下你试过但不管用的判据

省得下次再试一遍。我们的：**「bbox 高度占画幅比例」判不了景别** ——
全身 0.847、近景 0.856，近景的腿被裁掉之后 bbox 一样满画幅。只有关键点行。

## ③ ⛔ 存疑一律不放行，但存疑也要重抽

两件事，别只做一半：

- **不放行**：让一张存疑的首帧混进不可中断的下游，代价是整集重跑；
  漏跑一镜，早上补一条命令就行。**两边代价差一个量级，所以永远选扣下。**
- **也要重抽**：夜里 GPU 反正闲着。换个种子再抽，抽到判得明确为止；
  抽完还存疑才认，扣下留给早上人眼看。

## ④ ⛔ 跨镜一致性：只对阳性证据动手，不对证据缺失动手

单张全合格，连起来照样穿帮 —— 这一张枪在左手，下一张枪在右手。
这类判据的语义和上面几条**不一样**，必须写死：

> **只在两张都测准、且互相矛盾时才判不合格。「测不出来」不算证据。**

理由是这类特征天然大量缺失：跪姿必然有一条腿被遮，我们实测 8 张跪姿图里
只有 3 张能同时测到两个膝关节。把「看不出来」当不合格，会把整幕全扣下。

配套的两条：

- **判据要有前置条件。** 「枪在哪只手」靠找画面里的长竖线再量离哪只手腕近 ——
  但如果这一镜的枪是**杵在地上**的，最近的手腕纯属噪音。
  所以这条只在分镜声明了「握着」时才启用。
- **拿不准的量只报数、不判定。** 比如躯干色偏移，我们只把 Lab 均值打进报告让人看，
  不拿它扣图 —— 那个检测器只用 4 个样本标定过，当卡尺一定误伤。

### ⛔ 两个把这类判据变成随机杀手的 bug —— 都是我们真栽过的

**（a）平局不是多数派。**
跨镜判据一般写成「少数服从多数」，多数派当基准、少数派判不合格。
但这类特征天然大量缺失，**经常只有 2 张测得出来**，而 2 张一旦意见相反就是 1 比 1。
`max(counter)` 在平局时按字典序挑一个，等于**抛硬币判死一镜**。
症状很好认：报告里写着「其余 **1** 镜是…」—— 1 不是多数。

> 修法：`if cnt[基准] < 2: 不判，只打印「各执一词、没有多数派，人看一眼」`。
> 真平局说明两镜确实矛盾，但机器说不清谁对 —— 交给人，别自己拍板。

**（b）姿态判据要拿「入镜姿态」比，不能把入镜和出镜拼起来。**
如果分镜里的姿态字段是 `(入镜姿态, 出镜姿态)` 这种二元组（用来串姿态链的），
判据里千万别 `" ".join(pose)` 再去匹配关键词 —— **关键帧画的是入镜那一刻**。
我们有一镜是 `(低架式, 单膝跪)`，关键帧画的是他正从低架式起身、根本没跪，
拼起来却匹配到 "one knee"，于是拿一张没跪的图量出「跪左腿」，
再去跟真的跪着的另一镜打架，把那一镜判成穿帮 —— 连着两轮误杀。

这两个 bug 有个共同形状：**判据本身没错，错在它被喂了不该判的输入。**
上岗回归（第②节）只查了误杀率，查不出这个 —— 因为回归素材里恰好没有平局、
也没有姿态会中途变化的镜。**判据的前置条件要跟着素材一起复查。**

## ⑤ 重抽要有次数上限，废稿移走留证不要删

- **上限**：别拿一夜 GPU 去磨一张图。抽不出来就认，扣下。
- **留证**：废稿移到回收目录，文件名带轮次（`K4_r0.png` `K4_r1.png`）。
  早上要能看见它到底抽成了什么样，才分得清**是提示词的问题还是运气问题** ——
  三轮抽出来是同一种错，那是提示词；三轮各错各的，那是运气。
- ⛔ **过了就冻结，后面几轮不许再动它。**
  跨镜判据（第④节）是**拿本镜跟别的镜比**出来的 —— 于是重抽邻镜会把一个
  自己一个像素没变的镜从 PASS 翻成 FAIL，它跟着进重抽名单，那张已经合格的图
  就被当废稿移走了。我们真丢过一张：某镜第 5 轮以合格值放行，第 6 轮重抽邻镜后
  被判穿帮、好图被扔，**再抽 3 轮都没抽回来**（8 次抽样里只有那一张过线）。
  修法是维护一个 `frozen` 集合，进过放行名单的镜此后只维持放行、不再参与重抽。
  链判据出分歧时该重抽的是**还没过的那一边** —— 已经过的那张是当前唯一的
  既成事实，拿它去赌不划算。

  ⚠️ 冻结只在一次跑批内有效。下一次跑批从头判，还是会翻 —— 这是对的，
  因为素材可能已经变了。**但要能从回收目录把误扔的图捞回来**，
  所以上面那条「废稿留证不要删」是这条的兜底，不是可选项。

## ⑥ 说清楚机器判不了什么，别让它假装能判

**画风、情绪、构图好不好看 —— 机器判不了。** 报告里要明写这句。

一份不说自己边界的验收报告，最坏的结果是让人以为"全绿 = 可以出片"，
从而跳过早上那一遍人眼。我们的夜跑报告固定带这段：

```
机器只判：背对 / 左右分区 / 全景全身 / 物件镜塞脸 / 黑图 / 跨镜一致性。
画风、情绪、构图美不美它判不了 —— 这部分还得你看 _审片_*.png。
```

## 编排：一轮完整的夜跑长什么样

```
出关键帧 → ┌ 逐张验收 ─→ 跨镜一致性 ─→ 合格？
           │                              ├ 是 → 放行清单
           │                              └ 否 → 废稿移走留证
           └───────── 换种子重抽（≤N 轮） ←─┘
                                  ↓ 轮次用尽
                      扣下 + 写进报告 → 只把放行的送进下游
```

三条安全性质，改脚本时别破坏：**存疑一律不放行 / 重抽有上限 / 废稿不删只移走**。
